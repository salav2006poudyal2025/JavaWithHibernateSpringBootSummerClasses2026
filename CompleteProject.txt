MY SPRING WEB - COMPLETE PROJECT DOCUMENTATION
===============================================

1. WHAT THIS PROJECT IS
-----------------------

Project name: MySpringWeb

MySpringWeb is a Java Spring Boot web application. It lets a person create an account, sign in, see the user list, edit user details, upload images, and use a REST API. It also sends a welcome email after registration, supports JWT tokens for API clients, and can store cloud images in Cloudinary.

There are two ways to use the project:

1. Website use in a browser through the HTML pages.
2. API use through REST endpoints and JWT Bearer tokens.

Main technologies: Java 17, Spring Boot 4.1.0, Spring MVC, Thymeleaf, Spring Data JPA/Hibernate, MySQL-compatible database, H2 test database, Spring Security, BCrypt, JJWT, Spring Mail, Cloudinary, Maven, Docker, and Render.


2. WHAT WAS IMPROVED
--------------------

Signup is now faster
~~~~~~~~~~~~~~~~~~~~

The welcome email was previously sent before the signup response finished. Sending email can be slow because it depends on the SMTP server and internet connection.

The project now uses @EnableAsync in MySpringWebApplication.java and @Async in EmailService.java. The new flow is:

1. The user account is saved.
2. The browser redirects to the login page immediately.
3. The welcome email is sent in the background.

This removes SMTP waiting time from signup.

Sign-in work reduced
~~~~~~~~~~~~~~~~~~~~

SQL output is now disabled in application.properties with spring.jpa.show-sql=false. The datasource driver was updated to com.mysql.cj.jdbc.Driver. Login performs one user lookup and BCrypt password verification.

If login is still slow, check the database server and network. Login must contact the database. A distant, sleeping, overloaded, or slow cloud database will make login slower.

Edit flow fixed
~~~~~~~~~~~~~~~

The old edit form did not send the email value. It also sent the stored password hash back to the browser in a hidden field. The new edit flow is safe and complete:

1. editPage.html sends user id, username, and email.
2. UserController loads the saved user from the database.
3. Only username and email are changed.
4. The BCrypt password and image links remain unchanged.
5. The browser redirects to Home and displays a success message.
6. If a signed-in user changes their own username, the session username is updated.

The password hash is no longer sent to the browser in the edit form.

Files changed for these improvements:

* MySpringWebApplication.java
* EmailService.java
* UserService.java
* UserServiceImpl.java
* SignupController.java
* UserController.java
* RControllerClass.java
* editPage.html
* home.html

4. HOW THE APPLICATION STARTS
-----------------------------

Starting file: src/main/java/io/herald/MySpringWeb/MySpringWebApplication.java

The main method runs SpringApplication.run(MySpringWebApplication.class, args).

Spring Boot then:

1. Finds Java classes under io.herald.MySpringWeb.
2. Creates classes marked with @Controller, @Service, @Repository, @Component, and @Configuration.
3. Reads application.properties.
4. Connects to the configured database.
5. Creates Hibernate/JPA entity mappings.
6. Sets up Spring Security, the JWT filter, mail sender, and Cloudinary client.
7. Starts the application on port 8080.

Local URL: http://localhost:8080/


5. CREDENTIALS: WHAT TO ADD AND WHERE TO STORE THEM
----------------------------------------------------

Important rule: never put real passwords, API keys, or secrets in application.properties or Git. application.properties contains only placeholders. The real values are read from environment variables when the application starts.

File: src/main/resources/application.properties

Database credentials
~~~~~~~~~~~~~~~~~~~~

The application reads:

DB_URL=${DB_URL}
DB_USERNAME=${DB_USERNAME}
DB_PASSWORD=${DB_PASSWORD}

Add these manually:

* DB_URL - JDBC database address. Local MySQL example: jdbc:mysql://localhost:3306/myspringweb
* DB_USERNAME - database user name, for example root.
* DB_PASSWORD - database password.

Database data location:

* UserTable stores user id, username, email, and the BCrypt password hash.
* ImageTable stores local image data as Base64 text.
* ImageTable2 stores Cloudinary secure HTTPS image URLs.

Passwords are not stored as plain text. UserServiceImpl uses BCryptPasswordEncoder. The original password is changed to a BCrypt hash before storage. Login compares the password typed by the user with that hash.

Mail credentials
~~~~~~~~~~~~~~~~

The application reads:

MAIL_USERNAME=${MAIL_USERNAME}
MAIL_PASSWORD=${MAIL_PASSWORD}

SMTP settings already in the project:

* Host: smtp.gmail.com
* Port: 587
* SMTP authentication: enabled
* STARTTLS: enabled

Add manually:

* MAIL_USERNAME - Gmail address that sends welcome email.
* MAIL_PASSWORD - Gmail App Password.

For Gmail, enable 2-Step Verification first. Create an App Password in Google Account security settings. Use that App Password as MAIL_PASSWORD, not the normal Gmail password.

EmailService now uses MAIL_USERNAME as the sender address. It does not contain a hard-coded sender email.

JWT credentials
~~~~~~~~~~~~~~~

The application reads:

JWT_SECRET=${JWT_SECRET}
jwt.expiration=86400000

Add manually:

* JWT_SECRET - a long, random private secret, at least 32 characters.

JWT_SECRET signs API tokens. Keep it private. The configured token lifetime is 86,400,000 milliseconds (24 hours).

Cloudinary credentials
~~~~~~~~~~~~~~~~~~~~~~

The application reads:

CLOUDINARY_CLOUD_NAME=${CLOUDINARY_CLOUD_NAME}
CLOUDINARY_API_KEY=${CLOUDINARY_API_KEY}
CLOUDINARY_API_SECRET=${CLOUDINARY_API_SECRET}

Manual steps:

1. Create/sign in to Cloudinary.
2. Open the Cloudinary dashboard.
3. Copy Cloud Name, API Key, and API Secret.
4. Add them to environment variables with the names above.

Where to enter credentials locally
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Open PowerShell in the project folder and enter values before starting the app:

$env:DB_URL="jdbc:mysql://localhost:3306/myspringweb"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="your_database_password"
$env:MAIL_USERNAME="your_email@gmail.com"
$env:MAIL_PASSWORD="your_gmail_app_password"
$env:JWT_SECRET="put_a_long_random_secret_here"
$env:CLOUDINARY_CLOUD_NAME="your_cloud_name"
$env:CLOUDINARY_API_KEY="your_cloudinary_api_key"
$env:CLOUDINARY_API_SECRET="your_cloudinary_api_secret"

These values stay only in that PowerShell session. Start the application from the same window.

Where to enter credentials on Render
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

In the Render service dashboard, open Environment and add the same values. render.yaml already contains all variable names. Enter only values in Render; do not add them to source code or Git.


6. DATABASE SETUP
-----------------

The production project uses a MySQL-compatible database.

Manual steps:

1. Install MySQL or create a cloud MySQL/TiDB database.
2. Create an empty database, for example:

   CREATE DATABASE myspringweb;

3. Create a database user if required.
4. Set DB_URL, DB_USERNAME, and DB_PASSWORD.
5. Start the application.

The project has spring.jpa.hibernate.ddl-auto=update. Hibernate uses it to create/update entity tables at application startup.

Data structure:

UserTable
* id - generated user id.
* username - user name.
* email - user email.
* password - BCrypt password hash.

ImageTable
* id - generated local image id.
* image - Base64 image content.
* user_id - link to the user.

ImageTable2
* id - generated cloud image id.
* imageUrl - secure Cloudinary image URL.
* user_id - entity relation field.

One user can have many ImageTable records and many ImageTable2 records.


7. WEBSITE USER FLOW
--------------------

Landing page
~~~~~~~~~~~~

Route: GET /
Controller: MappingClass.java
Page: firstPage.html

The visitor sees the first page and can choose Signup or Login.

Signup
~~~~~~

Route: GET /signup and POST /signup
Files: SignupController.java, signup.html, UserServiceImpl.java, EmailService.java

Flow:

1. Visitor opens /signup.
2. signup.html shows username, email, and password fields.
3. Visitor submits the form.
4. SignupController checks that values are not empty.
5. SignupController checks whether the username already exists.
6. A UserTable object is created.
7. UserServiceImpl.registerUser saves it.
8. UserServiceImpl hashes the raw password with BCrypt.
9. UserRepository saves through JPA/Hibernate.
10. EmailService starts the welcome email in the background.
11. Browser redirects to /login with a success message.

Login
~~~~~

Route: GET /login and POST /login
Files: MappingClass.java, login.html, UserServiceImpl.java

Flow:

1. User enters username and password.
2. MappingClass checks that values are present.
3. UserServiceImpl finds the user by username.
4. BCrypt compares the typed password with the stored hash.
5. If correct, an HttpSession is created.
6. Username is saved as session.username.
7. Browser redirects to /home.

Home page
~~~~~~~~~

Route: GET /home
Files: MappingClass.java, home.html

The controller gets all users through UserService.findAllUsers. home.html uses Thymeleaf th:each to display them and gives Edit/Delete buttons.

Edit user
~~~~~~~~~

Routes: POST /editUser and POST /updateUser
Files: UserController.java, editPage.html, home.html

Flow:

1. Click Edit on Home.
2. UserController finds the selected user by id.
3. editPage.html opens with username and email.
4. Change username/email and click Save Changes.
5. UserController loads the current database record.
6. It updates username and email only.
7. The existing BCrypt password and image links stay safe.
8. Browser returns to Home with a success message.

Delete user
~~~~~~~~~~~

Route: POST /deleteUser
File: UserController.java

The controller receives an id, then calls UserService.deleteUser and UserRepository.deleteById.

Logout
~~~~~~

Route: GET /logout
File: MappingClass.java

The current HttpSession is invalidated and the browser returns to /login.


8. IMAGE GALLERY FLOW
---------------------

Local gallery
~~~~~~~~~~~~~

Routes: GET /gallery and POST /gallery
Files: GalleryController.java, galleryPage.html, ImageTable.java, ImageRepository.java

Flow:

1. A logged-in user opens /gallery.
2. GalleryController checks session.username.
3. User selects an image and submits the multipart form.
4. MultipartFile provides the image bytes.
5. Bytes are converted to Base64 text.
6. ImageTable is saved through ImageRepository.
7. The image is linked to the session user when found.
8. session.totalImages is refreshed.
9. galleryPage.html displays Base64 image data.

Cloudinary gallery
~~~~~~~~~~~~~~~~~~

Routes: GET /gallery2 and POST /gallery2
Files: GalleryController.java, CloudinaryConfig.java, galleryPage2.html, ImageTable2.java, Image2Repository.java

Flow:

1. User opens /gallery2.
2. The controller loads saved cloud image records.
3. User selects an image and posts multipart data.
4. GalleryController gets bytes from MultipartFile.
5. It uploads bytes through cloudinary.uploader().upload().
6. Cloudinary returns an upload result.
7. GalleryController reads secure_url.
8. The secure URL is saved in ImageTable2.imageUrl.
9. galleryPage2.html displays the HTTPS image URL.

CloudinaryConfig sets secure=true, so delivered Cloudinary URLs use HTTPS.


9. EMAIL FLOW
-------------

Files: EmailService.java, UserServiceImpl.java, application.properties

After UserServiceImpl.registerUser saves a new user, it calls EmailService.sendRegistrationEmail.

EmailService:

1. Creates SimpleMailMessage.
2. Uses MAIL_USERNAME as sender.
3. Uses the new user's email as receiver.
4. Adds a welcome subject and message.
5. Uses JavaMailSender to send through SMTP.
6. Runs in background using @Async.

STARTTLS is enabled in application.properties for encrypted SMTP transport.


10. SECURITY AND PASSWORD PROTECTION
------------------------------------

Files: SecurityConfig.java, UserServiceImpl.java, JWUtil.java, JwtAuthenticationFilter.java

Spring Security permits public access to:

* /
* /login
* /signup
* /css/**
* /js/**
* /images/**
* /api/auth/**

Spring Security requires authentication for /api/**.

Website pages use browser HttpSession. API clients use JWT Bearer tokens.

BCrypt
~~~~~~

SecurityConfig creates BCryptPasswordEncoder. UserServiceImpl hashes new raw passwords. Login uses passwordEncoder.matches to compare the typed password with the stored hash. The database does not hold the original password.

JWT
~~~

Files: JWUtil.java, JwtAuthenticationFilter.java, AuthRestController.java

API login route: POST /api/auth/login

When correct API credentials are given, AuthRestController calls JWUtil.generateToken and returns:

{"token":"JWT_VALUE"}

JWT flow:

API client
  -> POST /api/auth/login
  -> BCrypt password check
  -> JWUtil creates HS256 signed token
  -> API returns token
  -> client sends Authorization: Bearer TOKEN_VALUE
  -> JwtAuthenticationFilter reads/validates token
  -> SecurityContextHolder stores authenticated username
  -> Spring Security allows protected /api/** request

JWUtil reads JWT_SECRET and jwt.expiration. It stores the username as token subject, adds issue/expiry times, signs with HS256, and validates the token.

CSRF
~~~~

SecurityConfig uses csrf.disable(). This is the current setting for the project form/API setup.


11. REST API DOCUMENTATION
--------------------------

Files: RController/RControllerClass.java and RController/AuthRestController.java

Public API:

POST /api/auth/login
* Request parameters: username and password.
* Correct credentials: HTTP 200 and JSON token.
* Incorrect credentials: HTTP 401 UNAUTHORIZED.

Protected API: add this header first:

Authorization: Bearer YOUR_JWT_TOKEN

GET /api/hello
* HTTP 200, Hello World.

GET /api/users
* HTTP 200 and all users.
* HTTP 204 when there are no users.

GET /api/users/{id}
* HTTP 200 and one user.
* HTTP 404 when the id is not found.

POST /api/users
* Receives JSON user data.
* Creates user and starts welcome email in background.
* HTTP 201 CREATED.

PUT /api/users/{id}
* Receives JSON update data.
* Updates user.
* HTTP 200 and updated user.

DELETE /api/users/{id}
* Deletes user.
* HTTP 204 NO CONTENT.

Example login request:

POST http://localhost:8080/api/auth/login?username=your_username&password=your_password


12. ERROR HANDLING AND VALIDATION
---------------------------------

Files: GlobalExceptionHandler.java and UserNotFoundException.java

The project uses ResponseEntity for clear API response codes:

* 200 OK - successful read, login, or update.
* 201 CREATED - successful creation.
* 204 NO CONTENT - empty result or successful delete.
* 400 BAD REQUEST - validation error.
* 401 UNAUTHORIZED - invalid API login.
* 404 NOT FOUND - user not found.
* 500 INTERNAL SERVER ERROR - unexpected server error.

GlobalExceptionHandler has @ControllerAdvice. This lets the project handle common errors in one place. UserNotFoundException is the custom error for an unavailable user id.

UserTable uses:

* @NotBlank for username.
* @NotBlank for password.
* @NotBlank and @Email for email.

        |

Presentation layer
* Files: templates/*.html and static/css/styles.css.
* Shows forms, tables, image galleries, links, and messages.

Controller layer
* Files: Controller/*.java and RController/*.java.
* Receives browser/API requests.
* Normal controllers return HTML view names.
* REST controllers return ResponseEntity responses.

Service layer
* Files: UserService.java, UserServiceImpl.java, EmailService.java.
* Handles user save/find/delete, BCrypt hashing, authentication, and welcome email work.

Repository layer
* Files: UserRepository.java, ImageRepository.java, Image2Repository.java.
* Uses Spring Data JPA for save, findById, findAll, deleteById, and findByUsername.

Model/database layer
* Files: UserTable.java, ImageTable.java, ImageTable2.java.
* Defines database columns and user-image relations.


14. JAVA AND SPRING CONCEPTS USED
---------------------------------

Classes/objects: UserTable, ImageTable, ImageTable2, controllers, services, filters, and configuration classes are Java classes. Controllers create user/image objects when needed.

Interfaces: UserService is implemented by UserServiceImpl. Repository interfaces extend JpaRepository.

Inheritance:
* JwtAuthenticationFilter extends OncePerRequestFilter.
* UserNotFoundException extends RuntimeException.
* Repositories inherit CRUD methods from JpaRepository.

Dependency injection: @Autowired injects UserService, repositories, PasswordEncoder, JavaMailSender, Cloudinary, and JWUtil.

Configuration/beans: @Configuration is used in SecurityConfig and CloudinaryConfig. @Bean creates PasswordEncoder, SecurityFilterChain, and Cloudinary objects.

File handling: GalleryController receives MultipartFile uploads. It either stores Base64 content locally or sends bytes to Cloudinary.

Stream handling: GlobalExceptionHandler uses Java Streams and Collectors.joining to combine validation messages.

JVM/runtime: the project uses Java 17. Docker also runs the packaged JAR on Java 17 Eclipse Temurin.

16. DOCKER
----------

File: Dockerfile

The Dockerfile has two stages.

Build stage:
1. Uses maven:3.9-eclipse-temurin-17.
2. Copies pom.xml and src.
3. Runs mvn clean package -DskipTests.

Run stage:
1. Uses eclipse-temurin:17-jre-alpine.
2. Copies the generated JAR to /app/app.jar.
3. Exposes port 8080.
4. Runs java -jar app.jar.

Example commands:

docker build -t my-spring-web .
docker run -p 8080:8080 --env-file .env my-spring-web

Keep .env private and do not commit it. It should use the credential names from section 5.

19. FINAL SUMMARY
-----------------

MySpringWeb is a full Spring Boot project that connects browser pages, Java controllers, business services, a database, email delivery, JWT API security, and Cloudinary image storage.

Complete flow:

Signup form
  -> controller checks values
  -> BCrypt hashes password
  -> database stores user
  -> background email starts
  -> user signs in
  -> browser session is created
  -> user can view/edit users and upload images
  -> API clients can request JWT tokens
  -> JWT protects /api/** routes
  -> images are stored locally as Base64 or in Cloudinary as secure URLs
  -> Docker and Render provide a deployment path

All sensitive values are outside source code in environment variables. The improved code no longer makes signup wait for email delivery and safely keeps saved user passwords/data during edit operations.
